# Методика попереднього порівняння на validation

Дата: **1 листопада 2026 року**. Це специфікація дослідницького кандидата й попередніх валідаційних експериментів. Формули групування, базові ваги, ручні коефіцієнти надійності та сітку параметрів визначено **до обчислення порівняльних результатів**. Доведення наукової новизни, калібрування ймовірностей і фінальне тестування не виконуються на цьому етапі.

## 1. Спільні вхідні ознаки

Для пари пропозицій використовуються чотири канали, у порядку `title`, `description`, `brand`, `identifier`. Усі методи зіставлення атрибутів отримують одну матрицю ознак; text-only baseline бере лише перший стовпець. Ціна, валюта, ID пропозицій, cluster ID та службова позначка hard negative не входять до similarity.

Нормалізація тексту: Unicode NFKC → casefold → згортання пробільних символів. Справжні null/NaN стають відсутністю, а не рядком `"nan"`. Для назв і описів використовуються окремі character TF-IDF 2–4-грами, `sublinear_tf=True`, `max_features=30000`, стандартна L2-нормалізація. Словники та IDF навчаються лише на унікальних за offer ID навчальних пропозиціях. Косинус — скалярний добуток нормованих векторів. Якщо хоча б один вектор нульовий, порівняння недоступне; це не спостережувана несхожість 0.

Бренди порівнюються точно після спільної нормалізації. `identifier` — Jaccard подібність множин евристично виділених буквено-цифрових токенів **із назв**. Це не окремий атрибут WDC й не перевірений MPN/GTIN. Якщо хоча б одна множина порожня, канал недоступний; якщо дві непорожні множини не перетинаються, similarity дорівнює 0. Евристика зберігається зі стартового прототипу, включно з відсіканням одиниць вимірювання та частини загальних технічних позначень.

Позначення: \(s_i\in[0,1]\) — доступна подібність каналу; \(m_i\in\{0,1\}\) — наявність порівняння з обох сторін. Недоступне значення зберігається як NaN. Подібність 0 має \(m_i=1\), відсутня — \(m_i=0\).

## 2. Що саме реалізував початковий adaptive

Історичний API `matching.scores` збережений без зміни формул для відтворюваності. Він має базові ваги

\[
w=(0.40,0.15,0.15,0.30),\qquad r=(1,1,1,0.70),\qquad e_i=w_i r_i d_i.
\]

Для доступних каналів початковий метод обчислює

\[
Q=\sum_i m_i e_i,\quad E=\sum_i e_i,\quad
M=\frac{\sum_i m_i e_i s_i}{Q},\quad C_{old}=\frac{Q}{E},
\]

\[
A_{old}=\operatorname{clip}_{[0,1]}\left[
C_{old}^{\gamma}M+(1-C_{old}^{\gamma})\pi
-p\,\mathbb{1}\{m_{id}=1,s_{id}=0\}\right].
\]

При \(Q=0\) результат примусово 0. `adaptive_no_coverage` повертає \(M\) зі збереженням відповідного конфліктного штрафу. На відміну від звичайного available-attribute renormalization, старий adaptive змінює відносні ваги через \(r_i d_i\), змішує середню подібність із \(\pi\) залежно від coverage та може додатково штрафувати евристичний конфлікт.

Однак при \(\gamma=1\), до clipping,

\[
A_{old}=\frac{\sum_i m_i e_i s_i}{E}
+\pi\left(1-\frac{Q}{E}\right)-p\,\mathbb{1}\{m_{id}=1,s_{id}=0\}.
\]

Це алгебраїчно зважене заповнення відсутніх similarity значенням \(\pi\), а не окрема складна модель достатності доказів. Вага `identifier` додавалася до coverage окремо від `title`, хоча обидва походять з однієї назви. Інформативність і ручна надійність також змінювали coverage: розрізнювальність, достовірність та обсяг доступних даних змішувалися в одному коефіцієнті. Штраф за нульовий identifier повторно використовував уже врахований нуль каналу. Ці властивості є підставою для явного уточнення до перегляду F1.

## 3. Спільне групування для трьох атрибутних методів

Новий API `matching.evidence_scores` використовує групи

\[
G_T=\{title,identifier\},\quad G_D=\{description\},\quad G_B=\{brand\},
\qquad W=(0.70,0.15,0.15).
\]

Усередині \(G_T\) початкове співвідношення ваг збережено: \(b_{T,title}=4/7\), \(b_{T,id}=3/7\). Одноканальні групи мають \(b=1\). Ваги не підбиралися за validation. Бюджет назви 0.70 дорівнює сумі початкових 0.40 і 0.30.

Для групи \(g\):

\[
z_g=\sum_{i\in G_g}b_{gi}m_i,\qquad a_g=\mathbb{1}\{z_g>0\},\qquad
C=\sum_g W_g a_g.
\]

Група назви має один бюджет доступності незалежно від того, чи є обидва її канали, чи лише один. Формально \(a_T=\max(m_{title},m_{id})\). Доступний похідний токен не додає другу незалежну порцію coverage. Показник \(C\) залежить лише від порівнюваності груп, не від інформативності, надійності або величини similarity.

Це **обмеження сумарного бюджету корельованих каналів**, а не доведення їхньої незалежності й не повна декореляція. `identifier` усе ще змінює подібність сімейства. Опис може повторювати назву, бренд може входити в назву чи опис; усунення цих залишкових залежностей не заявляється.

### Fixed Weighted Attribute Similarity

Без поправок якості внутрішня подібність групи

\[
h_g^{(1)}=\frac{\sum_{i\in G_g}b_{gi}m_i s_i}{z_g}\quad(z_g>0),
\qquad F=\sum_g W_g a_g h_g^{(1)}.
\]

Недоступні групи дають нуль, а недоступні канали всередині доступної групи перенормовуються. Точна назва реалізації — **Fixed Weighted Evidence-group Similarity**. Це явне уточнення початкового raw-attribute fixed: коли identifier відсутній, наявна назва зберігає бюджет сімейства 0.70, а не лише 0.40. Усі три основні атрибутні методи мають однакове уточнення.

### Available-Attribute Renormalization

\[
R=\frac{F}{C}\quad(C>0),\qquad R=0\quad(C=0).
\]

Точна назва — **Available Evidence-group Renormalization**. Єдина відмінність від нового fixed — перенормування між доступними групами. На відміну від adaptive, не застосовуються train-discriminativeness, ручна reliability або shrinkage.

## 4. Adaptive Evidence-Aware Similarity

Якість каналу задається як \(q_i=r_i d_i\). Для доступної групи

\[
v_g=\sum_{i\in G_g}b_{gi}m_i q_i,\qquad
U_g=W_g\frac{v_g}{z_g},\qquad
h_g^{(q)}=\frac{\sum_{i\in G_g}b_{gi}m_i q_i s_i}{v_g}.
\]

Для недоступної групи \(U_g=0\). Середня оцінка доступних доказів:

\[
H=\frac{\sum_g U_g h_g^{(q)}}{\sum_g U_g}.
\]

\(U_g\) враховує середню якість **лише наявних** каналів. Наприклад, відсутній identifier із reliability 0.70 не зменшує надійність доступної назви. Водночас title/identifier продовжують ділити один початковий груповий бюджет. Остаточна оцінка основного методу:

\[
\boxed{A=C^{\gamma}H+(1-C^{\gamma})\pi},\qquad \pi=0.20.
\]

При відсутності всіх доказів результат 0; результат обмежується \([0,1]\). **Основний grouped adaptive має \(p=0\)**, щоб додатковий евристичний штраф не дублював уже врахований нуль identifier. Аргумент `penalty` збережений лише як явно позначена можливість діагностики; він не є складовою основного порівняння.

Відмінності від звичайного renormalization: \(r_i d_i\) змінюють внутрішні та міжгрупові відносні ваги, а \(C^\gamma\) змінює шкалу оцінки залежно від доступності сирих груп. При \(r=d=1\) та вимкненому coverage adaptive точно збігається з новим renorm.

\(C\) — лише **проксі повноти порівнюваних груп**, а не ймовірність правильності чи емпірично доведена достатність доказів. \(\pi\) — фіксована опорна точка шкали score, не оцінена posterior probability. Якщо \(H<\pi\), shrinkage підвищує score; якщо \(H>\pi\), знижує. Тому метод не гарантує зниження всіх неповних оцінок. Score не калібрований як ймовірність збігу.

## 5. Інформативність і надійність: зміст та межі

На train для кожного каналу обчислюються середні similarity серед доступних позитивних і негативних пар:

\[
\Delta_i=\overline{s}_{i,y=1,m_i=1}-\overline{s}_{i,y=0,m_i=1},\qquad
d_i=\operatorname{clip}_{[0.25,1.50]}(0.50+2\Delta_i).
\]

Потрібно щонайменше по три доступні спостереження кожного класу; інакше \(d_i=1\). Цю початкову формулу залишено для попереднього дослідження. Це глобальна **розрізнювальність каналу на навчальних парах**, а не Shannon information, рідкісність конкретного значення, каузальний внесок або похибка джерела. Вона не адаптується до конкретної назви. Пороги clipping і коефіцієнт 2 — евристики, не доведений оптимум. Повторення пропозицій у парах і корельованість каналів не усуваються оцінкою \(d_i\).

\(r=(1,1,1,0.70)\) — вручну заданий сценарій зменшення довіри до евристичного extractor. Значення 1 для інших каналів теж не доводить безпомилковості текстів чи брендів. WDC не дає незалежних gold extraction-confidence або достатньої інформації про довіру до вебджерел. Отже тут не навчається й не перевіряється справжня source reliability. Перемикання \(r_{id}=0.70\to1\) показує чутливість до ручної гіпотези, а не доводить, що 0.70 є точністю extractor.

Окрема межа ідентифікованості: у score входить добуток \(q_i=r_i d_i\). Без незалежної розмітки достовірності різні комбінації \(r_i,d_i\) можуть породжувати ту саму якість каналу. Три програмні перемикачі дозволяють окремі контрольовані sensitivity-абляції, але не ідентифікують справжню надійність незалежно від розрізнювальності та кореляції ознак.

## 6. Абляції та параметри, визначені до результатів

- Повнота: `adaptive_no_coverage` задає \(A=H\), зберігаючи \(r,d\).
- Інформативність: `adaptive_no_info` задає всі \(d_i=1\), зберігаючи coverage і \(r\).
- Надійність: `adaptive_no_reliability` задає всі \(r_i=1\), зберігаючи coverage і \(d\).

Три перемикання незалежні в реалізації; методи з однаковими або пропорційними коефіцієнтами можуть давати однакові результати. Основна сітка adaptive: \(\gamma\in\{0.5,1.0,1.5\}\), \(p=0\), \(\pi=0.20\); жодне значення не обирається за test. Інші коефіцієнти й представлення фіксовані як описано вище. Абляції успадковують обраний \(\gamma\), для кожної окремо добирається лише поріг на tune-validation.

Якщо \(C\) однакове для групи пар, повний score є додатним афінним перетворенням \(H\):

\[
A=C^\gamma H+(1-C^\gamma)\pi.
\]

Після відповідного перенесення порога ранжування й передбачення для такого прошарку не змінюються. Отже виграш F1 усередині незмінного availability pattern не можна приписати кращому ранжуванню через coverage. Внесок coverage можливий між різними patterns або через зафіксований поріг під новими пропусками. Порівняння з повторним добором порога та з незмінним порогом відповідають різним питанням; у стрес-тесті потрібен незмінний поріг.

Історичні raw fixed/renorm/adaptive можна зберегти як допоміжну діагностику з явним префіксом `legacy_`. Їхні групування, coverage і сітка параметрів відрізняються; порівняння не ізолює один чинник і не доводить перевагу нової архітектури. Основне парне порівняння — чотири заздалегідь описані методи зі спільною матрицею ознак і спільними групами, крім заявленого title-only baseline.

## 7. Область наукових висновків

WDC Products — загальний benchmark готових товарних пар; тут немає окремих технічних полів FPV-двигунів. Ці експерименти вимірюють Precision/Recall/F1 парної класифікації, не end-to-end повноту пошуку чи якість генерації кандидатів. Перевірка суто незалежного внеску достовірності джерел неможлива без додаткової розмітки. Модельні коди потребують ручного аудиту на train/validation, перш ніж трактувати їх як достовірні ідентифікатори.

Пропозиції повторюються в різних парах. Три seed маскування вимірюють розкид штучних масок, не довірчий інтервал для генеральної сукупності товарів. Природна неповнота й незалежне випадкове приховування полів — різні механізми. Гірший F1 adaptive не є підставою змінювати формули після результатів без нового окремо задекларованого досліду. Фінальний test зберігається для окремого погодженого етапу.

Офіційну [сторінку WDC](https://webdatacommons.org/largescaleproductcorpus/wdc-products/) та посилання на додаткові validation перевірено 01.11.2026. Завантажено `val_pair.zip` у локальний `data/external/valpair.zip`; він містить три вкладені ZIP, з яких перевірено `80pair_addvalid.zip`. Контрольні суми й детальні результати — у `docs/validation_data_audit.json`.

Обидва додаткові small-файли `050un` та `100un` містять однаковий розпакований JSONL. Кандидат `100un_valid_small` має 110 спільних пропозицій і 27 неупорядкованих пар із train; 250 з його 500 кластерів уже присутні у train. Це несумісно з використанням як незалежної повністю unseen-validation. Набір не очищували й не перейменовували для експерименту. Вибір зроблено за перевіркою цілісності, до будь-яких порівняльних F1.

Використано дозволений у постановці fallback — початковий `wdcproducts80cc20rnd000un_valid_small.json.gz`: 2500 пар, 500 позитивних і 2000 негативних. Із train спільних offer IDs та пар немає, але спільні всі 500 товарних кластерів, що відповідає seen-режиму. Відмінність від майбутнього unseen-test зберігається. Конфігурація — `docs/validation_config.json`; конфігурацію першого етапу не перезаписано.

Під час підготовки виконано лише metadata-проєкцію зарезервованого test для перевірки перетинів ID, кластерів і текстових відбитків. Поля label та is_hard_negative не використовувалися, не перевірялися й не агрегувалися; test predictions і метрики не обчислювалися. Сам експериментальний runner відкриває лише train та обрану validation.

## 9. Окремі частини validation для добору й звітування

Повторна оцінка на тих самих парах, де максимізовано F1 порога, мала б оптимістичне зміщення. Тому використано внутрішнє розділення validation за **товарними кластерами** до оцінювання методів:

1. Рядкові cluster IDs сортуються за SHA256 від `20261101:cluster_id` (лексичний ID — додатковий tie-break).
2. Перші 250 із 500 кластерів належать TUNE, решта 250 — REPORT. Seed `20261101` та частка 0.50 фіксовані; альтернативні розділення за F1 не шукалися.
3. Пара залишається в частині лише тоді, коли обидва її кінці належать цій частині. Пари між частинами виключаються з обох. Оригінальні файли залишаються без змін.
4. TF-IDF та d оцінюються на всьому train. Пороги і gamma обираються тільки на чистій TUNE. Після фіксації всіх конфігурацій REPORT використовується для чистих метрик, абляцій і маскування.

| Частина | Кластери | Пропозиції | Позитивні пари | Негативні пари | Усього |
| --- | ---: | ---: | ---: | ---: | ---: |
| TUNE | 250 | 500 | 250 | 479 | 729 |
| REPORT | 250 | 500 | 250 | 478 | 728 |
| Виключені міжчастинні пари | — | — | 0 | 1043 | 1043 |

Кластери та offer IDs TUNE/REPORT не перетинаються. Їхні кластери присутні в train, оскільки це seen-validation, але offer IDs із train різні. Виключення міжчастинних негативних пар змінює prevalence до 250/729 та 250/728 і може змінювати складність; це **внутрішній validation-протокол**, а не відтворення опублікованої повної benchmark-оцінки. Один partition не дає довірчого інтервалу. Його seed не включено до пошуку параметрів.

## 10. Вибір параметрів і метрики

Рішення про збіг: yhat = 1 тоді й лише тоді, коли score >= threshold. Кожен метод має власний поріг із фіксованої сітки 0.01, 0.02, …, 0.99; це також гарантує, що нуль без доказів не стає позитивним рішенням. Критерій TUNE — max F1, потім Precision, потім вищий поріг. При рівності всіх цих критеріїв для gamma зберігається порядок сітки. Основний adaptive обирає лише gamma із {0.5, 1.0, 1.5}; p=0, pi=0.20.

Для позитивного класу 1:

\[
P=TP/(TP+FP),\quad R=TP/(TP+FN),\quad F_1=2TP/(2TP+FP+FN).
\]

Нульовий знаменник дає 0. Confusion matrix має порядок [[TN,FP],[FN,TP]]. До вибору параметрів метрики не округлюються. Для абляцій gamma успадковується від повної моделі; поріг повторно добирається на TUNE. Окремо показано абляції зі збереженим порогом повної моделі. Ці два режими дають відповіді на різні питання.

Старі raw-attribute fixed/renorm/adaptive додано лише як заздалегідь заявлені діагностичні рядки з префіксом `legacy_`. Вони мають ті самі train/TUNE/REPORT і ознаки. Legacy adaptive зберігає стару сітку gamma × penalty = 3×3, тому його порівняння з головним adaptive не ізолює групування і має інший бюджет добору. Зміна правил після перегляду REPORT у цьому етапі не виконується.

## 11. Експеримент із неповнотою

Частки додаткового приховування p = 0%, 10%, 20%, 30%, 50%; seeds = 11, 22, 33. Для кожної унікальної пропозиції та окремо для description/brand обчислюється u з перших 64 біт SHA256(`seed:field:offer_id`), поділених на 2^64. Поле приховується, якщо u < p. Ті самі ID мають ту саму маску в кожній парі та при перестановці сторін; маски вкладені при зростанні p.

Пара втрачає description/brand similarity, якщо поле приховано хоча б в однієї сторони. Для спочатку порівнюваного поля пари з різними offer IDs очікувана частка втрати — 1−(1−p)^2, а не p. У JSON/CSV збережено також фактичну частку втрачених порівнюваних полів пари. Сирі природні пропуски залишаються. Пряме маскування цих двох стовпців матриці еквівалентне приховуванню відповідного атрибута пропозиції, оскільки вони не породжують інші канали. Title та identifier не приховуються.

Для кожної пари rate/seed всі методи отримують одну й ту саму пошкоджену матрицю REPORT. Представлення, інформативність, gamma та пороги залишаються незмінними. При p=0 три seed дають однакову чисту REPORT, а не три незалежні оцінки. Показуються середні та вибіркове SD (ddof=1) за трьома масками; це не довірчі інтервали й не оцінка всіх механізмів природних пропусків.

## 12. Відтворення

Залежності й Python 3.12 — як у README. Архів valpair автоматично не перезаписується. За наявності архівів:

```powershell
.\.venv\Scripts\python.exe -X utf8 prepare_validation.py
.\.venv\Scripts\python.exe -X utf8 run_validation.py --train data/external/wdcproducts80cc20rnd000un_train_small.json.gz --valid data/external/wdcproducts80cc20rnd000un_valid_small.json.gz --data-config docs/validation_config.json --out docs/validation/results.json
.\.venv\Scripts\python.exe -X utf8 report_validation.py --results docs/validation/results.json --out-dir docs/validation --report docs/validation_results.md
.\.venv\Scripts\python.exe -m pytest -q
```

Якщо valpair ще немає, `prepare_validation.py --download` завантажує його з офіційного джерела. `run_validation.py` не має аргументу `--test`; невідомий аргумент відхиляється до відкриття даних. Перед fit зберігається `docs/validation/protocol.json`; результат містить хеші джерельного коду, gzip train/validation та конфігурації. CSV/PNG/SVG відтворюються з JSON без повторного добору параметрів. Історичний `run_experiment.py` зі старим API лишається для відтворення стартового прототипу; у цьому етапі його фінальний CLI не запускається.

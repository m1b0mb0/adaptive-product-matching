# Маскування каталогу перед пошуком

`mask_catalog(catalog, fields, seed)` створює новий словник копій `ProductOffer`. Для кожного поля серед пропозицій з непорожнім `norm(value)` функція сортує пари «SHA-256 від UTF-8 рядка `{seed}:{field}:{offer_id}`, ID» і замінює перші `n // 2` значень на порожній рядок. Природні пропуски зберігають вихідне значення. Ключ маски однаковий для обох ролей пропозиції та всіх комбінацій полів із цим seed. Набір ID каталогу залишається повним.

Погоджені набори полів — `{title}`, `{brand}`, `{description}`, `{brand, description}` та `{title, brand, description}`. Seeds — 11, 22, 33. Кожен сценарій починається з чистого каталогу. Історичний pairwise-експеримент використовував імовірнісний поріг на хеші та застосовував маску до обчислених ознак пари. Точна квота й перебудова пошукових представлень стосуються наскрізного протоколу.

1. Отримати чисті пропозиції та перевірені qrels через `run_search_validation.load_inputs()`. Перед вимірюваннями звірити чисті агрегати й SHA канонічних результатів за запитами. [Контроль Task 6.3](wdc_validation_search_summary.json)
2. Побудувати всі каталогові представлення з результату `mask_catalog`. Запит і кандидати беруться із цього ж каталогу. `offer_to_pair()` проєктує його поточні поля, а `FeatureExtractor.transform()` витягає identifier із поточної назви. Frozen corrected використовує перевірений bundle із TRAIN-IDF.
3. Передати каталог, повний список query ID, чисті qrels, retriever та ініціалізовані ранжувальники у наявний `evaluate_search()` з параметрами Task 6.3. Один retrieval формує спільний пул для всіх методів. Запити з порожньою назвою мають порожній пул і нульовий внесок. Основні Candidate Recall@20, Hit@1, Hit@5 та MRR@5 усереднюються за всіма 1 000 запитами.
4. Після пошуку викликати `summarize_masked_validation(clean, masked, qrels, evaluation)`. Функція рахує природні та штучні пропуски, порожні назви й пули та частку запитів без відомої відповідності у пулі. Кожна підтверджена симетрична пара з двома збереженими назвами рахується один раз. Умовний MRR@5 усереднює внески лише за запитами, де збіг увійшов у пул до 20. Збіг на позиціях 6–20 дає нуль. За відсутності таких запитів умовне середнє невизначене (`None`).

Діагностика розрахована на validation із двома пропозиціями та однією підтвердженою парою на кластер. Два напрями цієї пари залежні. Штучна маска характеризує стійкість на раніше використаному validation; природні причини пропусків можуть відрізнятися.

Синтетична перевірка з оригінальним локальним frozen bundle запускається з кореня проєкту.


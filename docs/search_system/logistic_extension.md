# Точка підключення попередньо навченої Logistic Regression

Пошуковий API підтримує Logistic Regression через `FrozenLogisticPairScorer`.
Він приймає вже навчений `FeatureExtractor` і вже навчений
`SimilarityLogisticRegression`. Навчання, вибір конфігурації та завантаження
артефактів із диска не входять до цього інтерфейсу. Консольний прототип наразі
пропонує тільки `fixed` і `renorm`.

## Використання готових об'єктів у пам'яті

Приклад приймає каталог і готові об'єкти як аргументи. Він не навчає модель або
перетворення й не передбачає використання міток FPV чи зарезервованого TEST.

```python
from search_system import FrozenLogisticPairScorer, SearchEngine


def search_with_frozen_lr(catalog, extractor, model, query_id):
    scorer = FrozenLogisticPairScorer(extractor, model)
    engine = SearchEngine(catalog, method="logistic", pair_scorer=scorer)
    return engine.search(query_id, candidate_k=20, top_k=5)
```

Конструктор `FrozenLogisticPairScorer` перевіряє готовність компонентів через
`extractor.transform([])` і `model.metadata()`. Під час зіставлення він викликає
лише `extractor.transform(pairs)` та `model.predict_score(features)`. Методи
навчання не викликаються. Код, що передає ці об'єкти, відповідає за їхнє
походження, взаємну сумісність і незмінність після побудови пошукової системи.

## Два незалежні перетворення

Формування кандидатів використовує окремий TF-IDF-індекс назв, побудований
один раз із поточного каталогу без міток відповідностей. Це визначає лише те,
які пропозиції потрапляють до обмеженого набору кандидатів.

Для повторного ранжування Logistic Regression застосовується переданий
заморожений `FeatureExtractor` з його початковими словниками й IDF. Він не
замінюється перетворенням поточного каталогу. Модель отримує чотири подібності
та чотири індикатори доступності через наявний `SimilarityLogisticRegression`;
відсутня подібність залишається відмінною від спостережуваного нуля.

Назви, описи й бренди передаються через спільну проєкцію `offer_to_pair`.
Магазин, URL, технічні характеристики та інші додаткові атрибути не додаються
до similarity-ознак. Вони використовуються для відображення, а магазин також
може обмежувати кандидатів за джерелом.

## Контракт для іншого готового scorer

`PairScorer` визначає метод `score_pairs(pairs)`, що повертає одновимірний
масив із однією скінченною оцінкою в межах `[0, 1]` на кожну пару. Такий об'єкт
можна передати в той самий `SearchEngine(method="logistic", pair_scorer=...)`.
Він зобов'язаний використовувати вже навчені компоненти та не навчатися на
запитах. Для цього контракту поточний рушій перевіряє форму й діапазон
повернутих оцінок; походження або внутрішню реалізацію стороннього scorer він
автоматично не перевіряє.

Пошук не застосовує поріг класифікації та не повертає рішення про тотожність.
Для зовнішнього scorer поле `feature_similarities` результату дорівнює `None`:
цей контракт не вимагає окремого повернення діагностичних ознак.

## Що потрібно перед підтримкою артефакта на диску

Серіалізацію, десеріалізацію та CLI-завантаження LR-артефакта не реалізовано.
Збережені development-результати містять різні моделі й перетворення для
різних частин групової перевірки; вони не визначають одну погоджену фінальну
пошукову модель.

Майбутній артефакт повинен містити сумісний комплект: словники та IDF обох
текстових перетворень, параметри LR, порядок чотирьох similarity-ознак і
чотирьох індикаторів доступності, правила нормалізації та метадані версій і
походження навчальних даних. Випадок відсутнього текстового словника також
потрібно зберігати явно. Якщо надалі потрібна класифікація, її погоджений
поріг є окремим параметром; для теперішнього ранжування він не потрібний.

Самих коефіцієнтів із JSON недостатньо. Їх не можна поєднувати з новим
`FeatureExtractor`, навченим на поточному каталозі: зміна IDF змінює вхідні
подібності, для яких ці коефіцієнти було отримано.

Вихід LR тут є оцінкою алгоритму для ранжування. Зовнішню калібрацію як
ймовірності тотожності та перевагу за F1 цей інтеграційний механізм не доводить.
Зміна домену або повноти даних може змінити його поведінку. Підключення
інтерфейсу не запускає нового експериментального оцінювання.

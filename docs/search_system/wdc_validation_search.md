# Наскрізне оцінювання пошуку на WDC validation small

TF-IDF відібрав відому відповідність для **971 із 1 000 запитів**. Renormalization дав найвищі спостережені Hit@1, Hit@5 і MRR@5 на цих пулах. Порівняно з вихідним порядком TF-IDF він повернув відому відповідність першою ще для 40 запитів, а в першій п’ятірці — ще для 24 за чистою різницею. Це розвідувальний результат на раніше використаному validation.

| Порядок результатів | Candidate Recall@20 | Hit@1 | Hit@5 | MRR@5 | Збіг у пулі, але поза Top-5 |
|---|---:|---:|---:|---:|---:|
| TF-IDF за назвою | 0.971 | 0.351 | 0.758 | 0.495083 | 213 |
| Fixed Weighted | 0.971 | 0.379 | 0.769 | 0.517783 | 202 |
| Renormalization | 0.971 | 0.391 | 0.782 | 0.530900 | 189 |
| Frozen Adaptive corrected v1 | 0.971 | 0.377 | 0.758 | 0.514467 | 213 |

Усі 1 000 запитів допущено, виключено 0, порожніх пулів 0. Для 29 запитів збіг був відсутній серед кандидатів. Ці запити дають нуль за кожною метрикою. Candidate Recall@20 спільний для всіх рядків. За однієї відомої відповідності на запит він дорівнює retrieval Hit@20.

### Зміна позиції відносно TF-IDF

Знаменник для порівняння позицій — 971 запит зі збігом у пулі. Останні дві колонки показують перетин межі п’ятірки в кожному напрямку. Для corrected обидві групи мають по 72 запити, тож Hit@5 збігся з baseline попри зміну складу успішних запитів.

### Протокол та межі інтерпретації

Каталог містить 1 000 унікальних пропозицій. Із 2 500 анотованих пар `build_wdc_qrels()` перевірив 500 явних позитивів і побудував 1 000 спрямованих qrels. Запити йдуть за зростанням рядкового `offer_id`. Саму пропозицію виключено. Кластерні ID та мітки доступні лише оцінювачу. Міжкластерні пари без судження залишаються на своїх позиціях і мають невідому релевантність. Метрики характеризують знаходження відомих WDC-відповідностей. Повнота реальної товарної релевантності невідома.

Для кожного запиту TF-IDF формує один пул до 20 кандидатів без фільтрації за джерелом. Усі ранжувальники отримують той самий кортеж. Retrieval упорядковує за спаданням подібності назв, далі за ID. Ранжування впорядковує за спаданням similarity score, далі за retrieval score, далі за ID. Оцінювана глибина видачі — 5. Для аналізу зміщень збережено порядок у всьому пулі. Метрики усереднено за 1 000 запитами. Протокол і K зафіксовано до запуску.

Retrieval, Fixed і Renormalization використовують TF-IDF, побудований на тексті цього каталогу під час ініціалізації. Для corrected прикладний loader перевірив оригінальний bundle v1 зі збереженим TRAIN-fitted представленням. Скоринг усіх методів працював без класифікаційних порогів.

Validation уже використовувався в дослідженнях TUNE/REPORT. TRAIN і validation мають 500 спільних cluster_id та 0 спільних offer_id. Кожен із 500 кластерів дає два пов’язані запити, тому спостереження частково залежні. Узагальнення на нові товарні сутності та FPV потребує інших даних. Статистичну значущість тут не оцінювали. ### Відтворення

Контрольний повтор зафіксував 1 000 викликів retrieval і 3 000 викликів ранжування. Для кожного запиту перевірено ідентичність об’єкта пулу в усіх трьох ранжувальників. У циклі запитів перевірка переривала б запуск за будь-якого виклику `FeatureExtractor.fit`, `TfidfVectorizer.fit` або `TfidfVectorizer.fit_transform`. Прогін завершився, обидва запуски дали побайтово однакові JSON і JSONL. Окремий перерахунок із позицій у JSONL підтвердив метрики та зміни позицій.

Ревізія виконаного коду — `a3aef200eb9a533ed1bb3a0ba7956cd1b603989d`. Із чистого checkout цієї ревізії, у корені репозиторію, потрібні Python 3.12.10, пакети з `requirements-lock.txt`, локальні validation small та оригінальний bundle за шляхами маніфестів. Команда приймає нову вихідну директорію і зберігає попередні запуски. [Маніфест validation](../validation_config.json) · [Frozen-конфігурація](../final_method/frozen_configuration.json)

```powershell
.\.venv\Scripts\python.exe -B -X utf8 run_search_validation.py --out-dir results/wdc_search_validation_reproduction
Get-FileHash -Algorithm SHA256 results/wdc_search_validation_reproduction/per_query.jsonl
```

Компактний JSON фіксує повну точність агрегатів, версії пакетів і SHA-256 входів, qrels та деталей. Для SHA qrels ключі запитів і масиви позитивних ID впорядковані, JSON закодовано в UTF-8 без пробілів та кінцевого переносу. Деталі первинного запуску лежать у локальному `results/wdc_search_validation/per_query.jsonl` (каталог ігнорується Git). Один рядок містить query ID, відому відповідність, пул у початковому порядку, повні порядки за методами, позиції та внески у метрики.
